# 命令与副作用规范

- 运行命令前说明它服务于已确认计划中的哪一步，并了解命令会读取、写入或启动什么。
- 优先使用范围明确、影响可预期的命令。先检查脚本内容，再运行脚本；不要把“安装”或“更新”命令当作只读操作。
- 任何提权、软件安装或删除、网络访问、服务启停、权限变更、系统目录写入和外部账户操作，都必须在计划中列出具体目标和影响，并获用户确认后执行。
- 不因命令失败而自动改用更宽权限、扩大目标范围或追加副作用步骤；先查明原因，必要时更新计划。
- 不将完整环境变量、凭据、配置密文或可能含个人数据的命令输出贴入汇报。
- `install.sh` 涉及用户配置备份与链接、用户级 systemd 操作、SSH 权限调整，也包含可能使用 `sudo` 写入 `/usr/bin`、`/etc/pacman.d/hooks` 和 `/etc/pam.d` 的步骤。每次拟使用前重新检查脚本当前内容，并在计划中逐项说明会执行的部分和目标路径。
- README 明确要求不要以 root 身份运行 `install.sh`。不得用 root 绕过该限制。
