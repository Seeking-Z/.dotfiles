# Git 与改动隔离规范

- 修改前查看 Git 工作区状态，识别用户已有的暂存、未暂存和未跟踪改动。
- 用户已有改动一律视为保留内容；不要覆盖、重置、清理、暂存或纳入本任务。
- 若任务与已有改动重叠，先报告冲突和处理方案，等待用户确认。
- 完成后查看本任务涉及路径的差异，并确认没有混入无关文件。
- 使用精确路径进行审查和暂存；不要用 `git add .` 或同类宽泛操作收集改动。
- 不执行 `reset`、`clean`、强制检出、覆盖式恢复、提交、变基或推送，除非用户确认的计划明确包含该操作。
- Git 历史可用于理解配置演变，但提交内容可能含敏感信息；查阅时遵守 [`secrets-and-privacy.md`](secrets-and-privacy.md)。
