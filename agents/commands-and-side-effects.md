# 命令与副作用规范

- 运行命令前说明它服务于已确认计划中的哪一步，并了解命令会读取、写入或启动什么。
- 命令路径白名单、逐路径动作权限和范围判定统一遵循 [`repository-and-scope.md`](repository-and-scope.md)。每次运行前核对显式路径、隐式搜索范围及输出可能披露的对象；只读不授权修改，无法确认读取与输出均限制在批准范围内时停止，不用宽范围命令先行探查。
- Git 状态检查、差异审查、暂存、提交、恢复和远程操作遵循 [`git-workflow.md`](git-workflow.md)；提交或推送须列入已确认计划，远程操作与本地提交分别授权。提交钩子若可能执行超出计划的操作，先暂停并核实，不得擅自绕过或禁用。
- 优先使用范围明确、影响可预期的命令。先检查脚本内容，再运行脚本；不要把“安装”或“更新”命令当作只读操作。
- 任何提权、软件安装或删除、网络访问、服务启停、权限变更、系统目录写入和外部账户操作，都必须在计划中列出具体目标和影响，并获用户确认后执行。
- 不因命令失败而自动改用更宽权限、扩大目标范围或追加副作用步骤；先查明原因，必要时更新计划。
- 命令输出或报告可能包含本机敏感信息时，按 [`secrets-and-privacy.md`](secrets-and-privacy.md) 处理；只展示完成当前步骤所需的信息。
- 运行仓库脚本前，检查其当前实现，列明将执行的读写、删除、网络、权限、服务操作及目标路径；脚本名称、旧说明或历史执行结果不能替代检查。涉及配置部署时，同时遵守 [`deployment-and-activation.md`](deployment-and-activation.md)。
- 执行脚本前核对仓库当前说明中的权限限制；不得通过提权绕过这些限制。
- 若输出意外包含未授权路径名或内容，立即停止后续操作；不得在命令、截图或报告中复制、引用或转述越界信息，只报告偏差类型和影响。
