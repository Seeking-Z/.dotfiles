# 仓库发现与范围规范

- 先区分仓库中的源配置、生成文件、包清单、脚本和部署到系统后的目标文件。
- 仅在已确认的路径和查询范围内，结合目录结构、README、安装脚本、Git 跟踪状态和符号链接，确认某项配置的真实来源及应用路径；发现需要扩大范围时，先按工作流程提交修订计划。
- 只检查完成当前任务所需的文件。文件名可能含有凭据或个人信息时，先按 [`secrets-and-privacy.md`](secrets-and-privacy.md) 处理。
- 修改前明确任务涉及的文件和系统目标；避免顺手整理无关配置或大范围重排目录。
- 不把工作区当前主机等同于配置最终使用的主机。多主机或多系统差异按 [`system-context.md`](system-context.md) 判断。
- 对安装脚本和自动化脚本，先检查当前内容及其实际目标，再决定任务需要哪一部分；不要仅依赖 README 的旧描述。

## 命令路径范围门禁

- 已确认计划中的路径和对象清单是操作白名单；每项须标明允许的动作：读取内容、列出名称或元数据、编辑、创建、删除、移动或重命名。未列明的动作不获授权；只读或审查授权不包含修改授权。“仓库任务”不等于允许遍历整个仓库，路径未列入时不因其位于仓库或同一目录而自动获准。
- 对目录须注明授权的是目录项本身、直接子项还是递归子树；未注明时不得递归，也不得把列出名称等同于读取内容。符号链接本身与其目标是不同对象；除非目标路径及操作也获明确授权，否则不得跟随或读取目标。
- [`git-workflow.md`](git-workflow.md) 规定的全工作区 `git status --short --untracked-files=all` 是本节的固定范围例外，仅用于返回路径及 Git 状态并判断工作区是否有待处理条目；它不授权读取这些路径的文件内容、审查其差异、暂存、修改或提交。
- 每次运行命令前，将白名单与命令可能触及的对象逐项对照。除显式路径参数外，还检查当前工作目录、命令的默认范围、递归或跟随链接选项、shell 通配符与 Git pathspec 的展开范围，以及命令输出可能披露的路径名或内容。
- 危险操作的分类、逐项报备和执行前确认遵循 [`commands-and-side-effects.md`](commands-and-side-effects.md)；该确认不扩大本节的路径白名单或逐路径动作权限。
- 命令结果也是信息披露范围的一部分。使用能将读取和输出限制在已批准对象内的命令；需要时在输出进入会话前限定或筛选结果，但筛选输出不构成读取未授权对象的许可。若无法保证命令不会读取或输出未授权对象的信息，不要运行该命令，先改用范围更窄的方法或提交修订计划。
- 白名单有限时，给命令传入明确的文件或目录路径。`.`、`..`、仓库根目录、宽泛通配符、未限定的默认搜索范围，仅在其完整范围已获确认且可被明确限定时使用；否则先缩小命令范围或停止。
- 不要仅为确认已由环境或用户提供的工作目录而运行 `pwd` 或其他系统查询。若工作目录本身是任务必需数据，先在计划中写明查询目标和用途并等待确认。
- 若无法确认命令的完整触及范围，先不运行，改用范围更窄的方法；若需要扩大白名单，暂停受影响步骤，按已确认工作流程提交完整修订计划并等待确认。
- 若命令结果意外出现白名单外的路径、对象或内容，立即停止；不要打开、追查、复制、引用或对其运行后续命令。报告只说明发生了何种范围偏差及影响，不复述越界路径名或内容。
