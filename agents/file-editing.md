# 文件编辑规范

- 只改完成任务所需的最小范围，尽量沿用文件现有格式、命名、编码、换行、缩进和注释风格。
- 文件和代码结构遵循 [`workflow.md`](workflow.md) 的最小化原则：优先让每个文件承担一个主要职责；具有独立职责或可独立变化、复用、审查或测试的类和组件，考虑分文件。不要把“一文件一类”当作不顾语言惯例和代码内聚性的硬规则；紧密内聚的小型辅助类型可以留在同一文件。只有拆分能减少职责混杂或带来独立价值时才拆；若只增加跳转、依赖或维护负担，则保持整体。
- 保留配置的原有含义；不要为了美化而全文件重排、批量格式化或删除看似多余的注释。
- 修改前确认目标文件是仓库源文件，而不是链接目标、生成文件或系统副本。
- 修改机器专属选项前，确认它适用于目标环境；需要多机兼容时，优先沿用仓库已有的条件配置方式。
- 对锁文件、包清单和自动生成文件，只在任务明确需要时修改，并说明变化依据。
- 编辑包含凭据或私人信息的文件时，最小化读取、展示和复制；按 [`secrets-and-privacy.md`](secrets-and-privacy.md) 执行。
