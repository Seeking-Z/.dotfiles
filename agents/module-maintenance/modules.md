# 规范模块文件维护

本文件规定 `agents/` 中规范模块文件本身的新增、修订、移动、重命名、拆分、合并和删除。先遵守 [`../workflow.md`](../workflow.md)，并阅读 [`../module-maintenance.md`](../module-maintenance.md) 中的共用原则及目录树与索引规则；下文不重复定义索引维护流程。

## 新增模块

- 仅当主题边界清楚、独立成文能改善查找或维护，且不能自然归入现有模块时新增。规则数量不是唯一标准；少量但影响重大、需要单独查阅的规范也可成篇。
- 不为单次任务、瞬时状态、单个配置文件说明或可放入现有模块的零散规则新建模块。
- 新建前检查现有模块的职责、内容和索引入口，排除同义模块及容易混淆的归属。
- 使用稳定、易懂的文件名和标题；正文说明模块职责、适用情形和完整操作要求。需要时调整相关模块，以消除重复、冲突或流程缺口。
- 新模块从一开始就包含多个可独立查阅的子规范时，按“创建或拆分为多文件模块”流程建立父入口和子规范。
- 在存放位置的直接父入口登记新模块，并按共用目录树规则更新所有受影响的祖先索引和交叉引用。每个入口都要说明何时查阅，不能只留下无说明的文件链接。
- 若规范供不同工具或 agent 使用，确认目标工具实际支持文件位置及引用方式；不要假设一种工具的发现行为适用于所有工具。

## 修订、移动或重命名

- 先判断改动是措辞澄清、职责调整还是规范含义变化；保持仍有效的条件、例外和安全边界。
- 职责、适用范围或入口说明改变时，逐条检查内容归属，并按共用目录树规则更新父入口及所有受影响的祖先索引。移动文件或模块时同步调整来源、目标、标题及所有受影响的索引和交叉引用，并按共用目录树规则保持从 `AGENTS.md` 可达。
- 重命名或移动后搜索旧名称和旧路径；不要留下失效入口，也不要因整理结构无意改变规范含义。

## 拆分或合并

- 当模块包含适用情形不同、可独立查找的规范时考虑拆分；当模块职责重叠、内容难以归类或多个入口让查找更慢时考虑合并。
- 将模块拆成多个子规范时，按“创建或拆分为多文件模块”流程执行。
- 合并模块时先执行“合并模块（通用流程）”。需要新建目标模块时，同时按“新增模块”流程执行。
- 来源或目标含子规范，或合并会建立、重组子规范树时，执行“合并涉及子规范结构的模块”附加流程。
- 合并后新建或调整为多文件目标时，按“创建或拆分为多文件模块”流程维护目标结构。
- 所有适用步骤和最终核验完成后，按“删除模块”流程移除来源模块。

## 创建或拆分为多文件模块

- 先确定父模块的整体职责、适用范围和目标读者，再划分子规范主题；明确哪些要求适用于整个模块，哪些只适用于某个子规范，并为每条规则指定唯一归属。
- 创建新模块时，按确定的边界编写各子规范。拆分现有模块时，逐条迁移原内容，保留仍有效的要求、条件、例外、顺序和安全边界；不完整迁移前不删除原文。
- 编写或更新父入口时，先写模块整体说明和适用于所有子规范的共用要求；在文末设置子规范导航，逐项写明子规范名称、路径及何时查阅。具体规则留在对应子规范中，不在父入口复制全文。
- 按共用目录树规则更新父入口的直接子项、所有受影响的祖先索引及交叉引用；涉及已有子树时同步修正其内部链接和路径。
- 完成后检查父子职责边界、规则覆盖与重复、所有子规范的可达性和链接有效性；确认没有空壳入口、孤立文件或失去归属的规则。

## 合并模块（通用流程）

- 先确定保留或新建的目标模块及目标路径，盘点各来源模块及其后代中的主题、要求、条件、例外，以及相关索引、引用和依赖。
- 对照目标模块与各来源模块的职责和适用范围，逐项确定内容归属；保留仍有效的条件、例外、顺序和安全边界，澄清并解决冲突，合并重复内容，只保留一个权威版本。无法确定归属或是否仍适用时保留内容并询问用户，不擅自丢弃；结构调整不得默默改变要求的适用范围或强度。
- 更新目标模块的职责、范围和入口说明，并按共用目录树规则更新所有受影响的索引、交叉引用和路径。

## 合并涉及子规范结构的模块（附加流程）

- 在通用合并流程基础上，逐项映射来源父模块、子规范及其层级关系到目标结构；检查子规范职责重叠、名称冲突和适用范围差异。
- 将子规范迁入或重组到目标目录，按通用入口规则更新目标父入口的整体说明、共用要求和文末子规范导航；同步修正受影响后代规范的归属、链接和路径。

## 合并后的核验与来源移除

- 移除来源前，核对每项仍有效的要求都已迁移或经用户确认废止；检查目标入口及所有后代均可从 `AGENTS.md` 到达、链接有效、内容完整，并搜索确认没有指向来源模块的残留引用。
- 最终核验通过后，按“删除模块”流程移除来源模块及其已无内容的目录；保留仍含其他规范的目录。

## 删除模块

- 不因模块暂时未被任务使用或触发较少就删除。确认它已过时、重复或被完整替代。
- 删除前检查模块全文、所有后代文件、各级入口及其他文档中的名称、链接、规则引用和依赖；确认拟删除目录中没有计划外内容。
- 将仍有效的要求迁移到职责合适的模块；确认新位置完整覆盖后再删旧内容。无法确定是否仍适用时保留现状并询问用户。
- 删除后清理所有旧入口和路径，并按共用目录树规则处理子树；不留下空目录或仍被引用的孤儿文档。

## 完成检查

- 检查模块职责清楚、内容无重复冲突，所有仍有效的规则都有归属；新旧内容完整迁移，目标 agent 能理解应读取的规范范围。
- 涉及工具或 agent 的发现机制时，确认目标工具支持约定的位置和引用方式，不从一种工具的行为推断其他工具。
- 索引、链接、差异审查及计划范围检查统一遵循 [`../module-maintenance.md`](../module-maintenance.md) 的共用完成检查。
