# 命令与副作用规范

## 危险操作的判定与报备

- 按命令或工具调用的实际效果、目标范围、执行身份、环境和可恢复性判定风险，不以固定命令黑名单作完整定义。以下类别和命令只是非穷尽示例；功能等同的命令、参数组合和其他工具同样适用。
- 需要逐项报备并获用户确认的危险操作包括：删除、覆盖、截断、格式化或批量/递归改动数据；可能丢弃用户工作、改写 Git 历史或删除/强制更新远程引用的操作；提权、权限或安全策略变更；安装、卸载、升级软件，变更系统配置、服务或设备状态；部署、云/容器/集群/数据库写入、远程主机操作等外部状态变更；终止可能影响他人或服务的进程、任务或容器；可能造成服务中断、显著费用或不可逆影响的操作；向外部发送本机或用户数据、执行远程内容等数据外传或远程执行操作。例如 `rm`、`find -delete`、会覆盖目标的 `cp`/`mv`、截断重定向、`git reset --hard`、`git clean -f`、历史重写或强制推送、递归 `chmod`/`chown`、`sudo` 包装的系统修改、服务启停、`rsync --delete`、上传命令及 `curl | sh`。
- 同一命令可能因参数、当前目录、变量或通配符展开、目标数量、运行身份、服务/主机/账户、网络目的地和现有状态而产生不同风险。通过编辑工具对计划中明确列出的文件进行普通任务修改，仍按常规路径和动作权限授权，不因普通修改本身重复报备；若命令或工具还会删除、整文件替换、批量/递归写入、提权、部署系统或产生外部副作用，则仍按实际效果逐项报备。
- 危险效果不因换用别名、函数、shell 包装、脚本、解释器、管道、重定向、命令替换、`xargs`、`find -exec`、包管理器钩子、GUI、API、MCP 或其他工具而改变。运行前检查完整调用链及其实际目标；脚本和包装命令先检查当前实现。无法解析命令、目标、权限或副作用时，按未确认处理并暂停，不猜测其安全性。
- 计划阶段须将每项危险操作逐项写入计划，并按本节“报备格式”完整填写；只有用户确认该计划后才可执行。执行中发现未报备的危险操作时，先暂停该操作，按同一格式临时报备并等待用户明确确认。此前的任务确认、其他命令的批准、工具权限或平台审批均不代替这项确认。
- 确认仅适用于报备中的具体命令/调用、参数、目标、执行次数、执行环境、权限和预期效果；未明确次数时只授权执行一次。命令、解析后的目标、运行身份、目的地或影响发生变化，或预览发现范围扩大时，必须重新报备并确认。不得把一次确认解释为对某类命令或后续操作的概括授权。
- 能在批准范围内安全预览时，先用无副作用的检查确定实际目标并报告结果；预览或 dry-run 本身也须符合计划和路径白名单。预览不授权随后执行真实变更。无法确定实际目标或影响时停止并请用户决定。

### 危险操作报备格式

每项操作单独填写；命令包含多个可能独立产生副作用的步骤时，逐步列出，不用一行宽泛概括。不得在报备中暴露秘密或凭据；必要时用占位符标明敏感参数的来源。

```md
#### 危险操作（计划阶段 / 执行中临时报备）

- **命令或工具调用原文：** 完整命令、参数、管道、重定向、脚本入口及参数；非命令工具写明工具/操作名和完整参数。敏感值遮盖并说明其来源
- **用途：**
- **目标与范围：** 文件/目录、Git 引用、服务、主机、账户、数据集或外部目的地；说明数量及范围如何确定
- **执行次数与时机：** 执行次数、循环/批量次数及计划时机；无循环或重复时写“一次”
- **执行上下文：** 工作目录、运行身份/权限、环境或目标环境；不适用项写“无”
- **预期效果：** 将创建、修改、删除、发送、部署、启停或产生的其他具体变化
- **风险与可逆性：** 可能影响、波及范围、不可逆部分、服务中断/费用/数据外传风险及不确定点
- **预检或较安全替代：** 检查方式及其副作用；无时写“无”
- **恢复方式与限制：** 可恢复来源、恢复步骤及无法恢复的部分；无时写“无”
- **执行后验证：** 验证对象、方法和通过条件
- **临时报备原因：** 仅执行中临时报备时填写；计划阶段写“不适用”
- **确认请求：** 计划阶段请求用户确认计划及其中这项操作；执行中临时报备时，请求用户明确同意是否按上述范围执行这项操作
```

报备中的路径和参数须足以让用户辨认真实目标；本机私人路径或身份信息按 [`secrets-and-privacy.md`](secrets-and-privacy.md) 最小化披露，脱敏后若仍无法确认目标则暂停，不执行。

- 运行命令前说明它服务于已确认计划中的哪一步，并了解命令会读取、写入或启动什么。
- 命令路径白名单、逐路径动作权限和范围判定统一遵循 [`repository-and-scope.md`](repository-and-scope.md)。每次运行前核对显式路径、隐式搜索范围及输出可能披露的对象；只读不授权修改，无法确认读取与输出均限制在批准范围内时停止，不用宽范围命令先行探查。
- Git 状态检查、差异审查、暂存、提交、恢复和远程操作遵循 [`git-workflow.md`](git-workflow.md)；提交或推送须列入已确认计划，远程操作与本地提交分别授权。提交钩子若可能执行超出计划的操作，先暂停并核实，不得擅自绕过或禁用。
- 优先使用范围明确、影响可预期的命令。先检查脚本内容，再运行脚本；不要把“安装”或“更新”命令当作只读操作。
- 网络访问必须按 [`workflow.md`](workflow.md) 的联网查证规则列入计划、说明用途与范围并获用户确认。在已确认范围内打开和读取公开网页及在线文档属于资料查询；该授权不包括通过命令或其他工具将远程内容保存到本地文件、安装或执行内容、上传、向外部发送本机或用户数据、远程执行或改变外部状态。此类操作仍须按实际效果判定风险，达到危险操作标准时逐项按本节格式报备。
- 任何提权、软件安装或删除、服务启停、权限变更、系统目录写入和外部账户操作，都必须在计划中列出具体目标和影响，并获用户确认后执行；若属于危险操作，还须按本节格式逐项报备。
- 用户对计划或操作的确认只授予其明确列出的任务范围，不改变或替代工具、沙箱、平台审批或操作系统权限等独立边界；每次操作仍须符合这些控制。
- 工具拒绝操作或要求额外审批时，只能使用该工具或平台提供的正式审批流程，或停止并报告。不得通过其他工具、命令形式、身份或路径绕过同一限制。
- 不因命令失败而自动改用更宽权限、扩大目标范围或追加副作用步骤；先查明原因，必要时更新计划。
- 命令输出或报告可能包含本机敏感信息时，按 [`secrets-and-privacy.md`](secrets-and-privacy.md) 处理；只展示完成当前步骤所需的信息。
- 运行仓库脚本前，检查其当前实现，列明将执行的读写、删除、网络、权限、服务操作及目标路径；脚本名称、旧说明或历史执行结果不能替代检查。涉及配置部署时，同时遵守 [`deployment-and-activation.md`](deployment-and-activation.md)。
- 执行脚本前核对仓库当前说明中的权限限制；不得通过提权绕过这些限制。
- 若输出意外包含未授权路径名或内容，立即停止后续操作；不得在命令、截图或报告中复制、引用或转述越界信息，只报告偏差类型和影响。
