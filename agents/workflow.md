# 任务流程规范

本规范适用于本仓库任务的规划、执行、审查和汇报。按任务查阅相关模块；本规范不替用户决定目标、范围、偏好或取舍。

## 开始前：澄清并制定计划

- 明确目标、范围、约束和完成条件；区分可查证的事实与需要用户决定的事项。
- 持续拆分工作，直到每一步都是最小的、有单一结果、可独立执行和验收的工作单元；标明依赖和顺序。避免合并可独立完成的步骤，也避免没有独立结果的机械微步骤。
- 每一步说明动作、对象、预期结果和验收方式。计划还须列明涉及的文件或对象、范围与非目标、验证方法、风险及系统或外部影响；若需联网，列明查询目的和范围。路径范围要精确，并逐项区分读取内容、列出名称或元数据、编辑、创建、删除、移动和重命名权限；只读或审查不授权修改。目录要说明是目录项、直接子项还是递归子树，符号链接目标须单独列明。未列出的路径或动作不因命令默认范围而自动获准。
- 对需要偏好、取舍或授权的事项，不得依据猜测、默认值、惯例或个人倾向自行选择。列出已知事实、未知点、选项及影响，请用户决定。可通过检查或查证解决的事实，只有在计划确认后才能按计划核实；仍无法核实则暂停并询问。
- 计划须说明审查标准、复审方式，以及是否预先授权审查循环中的修正；若授权，必须限定可修正的问题类型、对象/文件范围和操作边界。用户确认只授权计划中明确写出的范围；未写明或有歧义时，发现问题后先提交修订计划并等待确认。
- 向用户提交计划并等待明确确认。确认前不读取仓库内容或系统状态，不运行命令，不联网，不编辑文件。

## 计划报送模板

提交计划时按以下顺序填写；必填项不得省略，不适用时写“无”。步骤须拆到可独立执行和验收，并列出依赖；文件范围写精确路径。

```md
## 计划

- **目标：**
- **范围与非目标：**
- **涉及文件或对象：** 精确路径作为允许范围；多个相关文件按树列出，并逐项标明读取内容、列出名称或元数据、编辑、创建、删除、移动或重命名权限。目录注明目录项、直接子项或递归子树范围；符号链接目标单独列明。未列入的路径或动作不自动授权；无文件改动时说明
- **步骤与依赖：** 每步写明动作、对象、预期结果和验收方式
- **验收标准：** 每项写明验证对象、方法和可观察的通过条件；暂时未知的验证方式写明查明步骤
- **审查与修正循环：** 审查方式、复审方式和结束条件；如用户明确要求最低审查轮数，写明轮数；明确列出预先授权修正的问题类型、对象/文件范围和操作边界，或写明“发现后先提交修订计划并等待确认”
- **风险与外部影响：**
- **联网报备：** 查证问题、用途和范围；不联网时写“未联网”
- **待用户决定：** 已知事实、未知点、选项及影响；无时写“无”
- **确认请求：** 请求用户确认或指出需调整之处

### 模板外补充内容（可选）

仅填写模板字段无法承载且与本任务相关的信息；不得借此扩大范围或授权。
```

修订已确认计划时，仍使用上方完整模板，完整列出修订后的当前计划，不只提交差异；未变化的范围和步骤注明沿用原批准计划。在“模板外补充内容”中列出基准计划、修订原因及发现依据、新增/调整/取消的步骤、已完成工作的保留方式和当前循环轮次。修订计划获用户明确确认前，暂停受影响步骤；若用户未确认或拒绝，不执行该修订或自行选择替代方案。不得用修订说明代替完整计划字段。

## 执行中：遵循已确认范围

- 按已确认的顺序、范围和方法执行，只进行计划列明或已获确认的操作与检查。
- 每次运行命令前，按 [`repository-and-scope.md`](repository-and-scope.md) 核对路径白名单与命令可能触及或列出的对象；不能确认命令限制在批准范围内时，先停止并缩小范围。
- 若发现计划外文件、风险、系统或外部影响，或需要扩大范围、改变实质方法，先暂停受影响步骤，按本节修订要求提交完整更新计划并等待确认；此前已完成且不受影响的步骤保留，不必重做。
- 遇到已有用户改动或文件冲突时，保留原状并报告；不覆盖、不清理，也不擅自更换目标。
- 若事实无法核实，或出现需要用户取舍的未决问题，暂停依赖该事项的步骤并询问；不得自行补全答案或选定方案。
- 命令失败或检查发现意外影响时，停止后续变更、保留现场并报告；不得为继续任务而自行扩大权限、重试高影响操作或恢复文件。

## 联网查证

- 联网操作必须列入已确认计划，并说明要查证的问题、用途和范围；用户直接提出联网要求也须遵守此流程。执行中发现计划未列明的联网确属必要时，暂停相关工作，补充计划并等待确认。查询限于当前任务。
- 优先使用能直接支持判断的一手或权威来源；社区资料用于参考和比较，不自动成为规范。记录所用来源的标题、链接及发布日期或适用版本，并区分来源陈述、基于来源的推断和未确认事项。
- 公开互联网资料可按已确认的查证范围检索；是否可以读取或向外发送本机数据，统一遵循 [`secrets-and-privacy.md`](secrets-and-privacy.md)。任务若看似需要超出该边界，暂停相关查询并请用户决定。
- 来源冲突、过时或不足以支持结论时，说明证据缺口；若这会影响任务选择或结论，暂停并请用户决定，不自行补成确定结论。
- 按已确认的任务范围使用查证结果；联网资料本身不触发额外的单独批准。若采用资料需要改变范围或作出尚未确定的取舍，仍须按本规范暂停并询问。汇报时列出查证来源及其用途。

## 验证标准与方法

验证用于判断具体验收条件是否满足；完整审查还要检查目标、范围、遗漏、冲突和整体差异。验证必须能证明计划中的验收条件，不能只写“检查无误”或“看起来正常”。每项验收条件都要对应验证对象、方法和可观察的通过条件；计划阶段尚不能确定具体方法时，说明如何查明，不能臆造命令或结果。

- 将已确认目标逐项对应到改动对象和验收条件，再反向检查没有遗漏目标或未经批准的增项。
- 根据改动对象选择足以证明结果的方法，可组合使用：
  - 文档和规范：检查 Markdown 语法和结构、要求覆盖、表述清楚、范围及前后规则一致、链接有效；涉及操作流程时，按下述场景走读验证。
  - 代码、脚本和配置：优先使用仓库已有的语法检查、格式检查、静态检查及相关测试，并检查改动实际影响的行为；不得为“验证”而假称未运行的检查通过。
  - 系统状态或有副作用的操作：按相关操作规范检查操作前状态；可行时先预览或试运行，再核对操作后状态与预期，并检查计划中的恢复条件。
- 流程或规范发生实质变化时，做场景走读：从 `AGENTS.md` 开始，只按最终规范逐层查找并模拟适用角色的行动。至少走通每条受影响主路径，并分别走查本次改动涉及的判断分支及其结果；覆盖适用的边界、例外、用户决定、暂停、失败和循环出口。记录场景、应到达的规则、应采取的动作或停止点及预期结果。无法确定下一步、审批点或完成条件时，记为发现项。
- 验证范围与风险相称：先检查直接改动，再检查受影响的依赖、引用和行为；修正后重跑失败项及受影响的回归检查，并重新审查完整结果。除非计划或风险要求，不以无关的全量检查代替针对性验证。
- 记录可复核的证据：实际命令或操作、涉及对象、必要的环境信息和简要结果。检查状态明确标为“通过”“失败”“未执行”或“不适用”；对未执行或不适用说明原因及影响。未执行的必需检查不能记为通过；若因此无法证明验收条件，按未决事项暂停或报告限制。

## 审查、修正与复审循环

若用户明确规定本计划的最低审查轮数，至少完成该计划规定的轮数；达到最低轮数后，完整复审无未解决发现时结束，有发现时继续修正和复审。若未明确规定最低轮数，每轮完整复审无未解决发现即可结束，有发现时继续修正和复审，直到完整复审无未解决发现。最低轮数只适用于所属计划，不自动延续到后续任务。

1. 按计划中的验收条件及本节验证标准检查目标、范围、完整差异、相关链接或依赖，以及实际验证证据。只报告实际完成的检查，不把计划中的检查说成已通过。
2. 逐项记录发现的证据、影响、涉及对象和可观察的修正后通过条件；不能确定问题或通过条件时，先查证或请用户决定，不猜测。
3. 对每项拟修正的问题，先写出最小独立修正步骤，列明动作、对象、预期结果和验证方法，再判断是否落在计划明确预先授权的类型、范围和操作边界内。符合且没有未决取舍时，可按已批准的循环授权执行，不必逐轮重复请求确认；计划未授权、描述含糊或修正需要用户决定时，暂停该项并按计划修订要求报批。
4. 完成获准修正后，执行该步骤的验证及受影响的回归检查，再对完整结果重新审查；发现新问题时继续从第 2 步循环。每次完整复审均计为一轮，局部修正或验证不单独计轮。
5. 只有完整复审没有未解决发现时，进入完成报告。若用户明确接受并记录特定剩余事项，可按该决定报告；等待用户决定时保持暂停状态，不得宣称审查通过。

只有所有发现均已修复并经复审通过，或用户已明确决定接受并记录特定剩余事项，任务才可标记完成。等待用户决定的事项仍未解决，不得宣称任务完成或审查通过。

## 完成或暂停报告

任务完成时，以及因等待用户决定而暂停时，按以下格式汇报；暂停状态不得标为完成。各项均须保留，无内容时写“无”。联网任务填写来源及用途；未联网时写“未联网”。

```md
## 报告

- **状态：** 完成 / 部分完成 / 等待用户决定
- **结果摘要：**
- **改动文件：** 文件路径及改动目的；无改动时写“无”
- **计划执行情况：** 已完成和未完成的步骤；无未完成步骤时写“无”
- **计划修订：** 提交次数、每次状态（获批 / 未获批）及获批的范围变化；无时写“无”
- **审查循环：** 完整审查轮数及发现项的处理结果
- **检查与验证：** 每项列验证对象、方法、状态（通过 / 失败 / 未执行 / 不适用）及结果；未执行或不适用时说明原因和影响
- **联网查证：** 实际查阅来源（标题、链接、日期或版本）及采用情况；未联网时写“未联网”
- **未决事项与限制：** 事项及需要用户决定的内容；无时写“无”

### 模板外补充内容（可选）

仅填写与任务相关且无法归入上述字段的补充信息；无时写“无”。
```

审查轮数从首次完整审查计为 1；每次修正后的完整复审再计 1 轮，局部验证不单独计轮。模板外补充内容不得替代、遗漏或与必填项矛盾，也不得暗示未获批准的范围变更。
