# 模块内规则维护

本文件规定规范模块内部规则的新增、修订、迁移、拆分、合并和删除。先遵守 [`../workflow.md`](../workflow.md)。父入口中的共用原则、目录树与索引规则适用于本文件。

## 新增规则

- 规则应说明可复用的操作或判断；不要把单次任务步骤、临时状态、纯背景说明或配置清单写成长期规范。
- 添加前搜索相同要求、近义表述和相关例外。已有规则能覆盖时，澄清或修订原规则，不另建重复版本。
- 新规则应填补已确认的规范缺口或表达稳定要求；不要因一次失误就堆加规则，也不要用新规则掩盖原规则含糊、难以发现或相互冲突。
- 将规则放在唯一且职责最匹配的模块。跨模块适用时保留一个权威正文，其他位置引用；范围确实不同则分别写明适用条件和关系。
- 将规则拆成最小且有意义的要求，写清适用条件、行动主体和应采取的行动；需要时说明顺序、禁止事项、例外或确认条件。
- 来源不确定、依赖尚未核实的系统事实或会改变用户授权边界时，先查证或询问，不把推断写成规定。

## 修订规则

- 明确修订目的，区分文字澄清与要求变化；保留仍有效的范围、限制、顺序和例外。
- 若同一错误或用户纠正反复出现，先检查规则是否含糊、过长、难以发现、与其他规则冲突或依赖已变化的事实；优先修正权威规则或入口，不叠加重复提醒。
- 检查引用该规则、依赖其前置条件或由其授权的其他规则；同步修改受影响的正文和引用，避免只改一处。
- 适用范围扩大或缩小时，明确新旧范围及必要的过渡关系，避免范围重叠但要求不同。
- 若规则修订导致模块职责、适用范围或查找路由改变，按共用目录树规则更新受影响的模块索引；单纯调整规则正文无需改索引。
- 对可能变化的仓库事实重新检查相关脚本、路径或行为；无法核实则暂缓相关断言或标明待确认。

## 拆分、合并或迁移规则

- 拆分时确保每条新规则仍包含必要条件、对象、限制和例外；合并前确认适用范围兼容且表述不会变含糊。
- 迁移或替换时逐项对照原要求与新位置，确保没有要求丢失、意外增强或削弱，也没有残留副本。
- 先写完整的新正文并更新引用，再删除旧表述；最终只保留一个权威版本。

## 删除规则

- 仅在规则过时、不再适用、重复或已被完整替代时删除。暂时未触发、很少使用或当前任务无关，不足以证明规则无用。
- 删除前检查其他规则和模块是否依赖它；部分内容仍有效时，先拆出并迁移有效部分。
- 删除重复规则时保留唯一权威版本，并将其他位置改为引用；删除过时规则时，清理失效引用和依赖它的前置说明。
- 若适用性、替代范围或依赖关系不明确，保留现状并询问用户，不猜测删除。

## 完成检查

- 检查受影响内容，确认每条现行规则归属明确、适用范围清楚、可执行，且没有重复或相互矛盾。
- 检查规则之间的前置关系和引用，避免循环依赖、孤立规则及无法判断应遵循哪一条的情况。
- 若维护由反复出现的问题触发，观察修订是否消除了歧义或发现问题；效果尚未确认时记录为待观察，不继续堆叠规则。
- 索引、链接、差异审查及计划范围检查统一遵循父入口中的共用完成检查。
