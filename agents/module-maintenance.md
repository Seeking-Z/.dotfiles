# 规范维护入口

本模块规定规范维护的共用原则、目录树与索引要求及完成检查。维护任务遵守仓库级工作流程 [`workflow.md`](workflow.md)；具体操作按维护对象查阅本文件末尾的子规范入口。

## 共用原则

- 规范内容应由用户明确要求、已确认决定、适用的更高优先级指令或可核实的仓库事实支撑；不得把猜测、临时状态或单次任务做法写成长期强制规范。
- 用户已确认的联网查证可作为分析依据，但外部资料和社区惯例本身不自动成为本仓库规则。采纳时核实其适用性并遵守已确认范围；若涉及用户取舍或范围扩大，按 [`workflow.md`](workflow.md) 暂停并询问。
- 每条规则只有一个权威正文；其他模块按需引用，避免复制后逐渐分歧。同一层级的规则不得依赖文件顺序决定优先级；发现冲突时在源头澄清范围、合并或修订，不确定时询问用户。
- 父入口中的共用规则适用于所有子规范；子规范只能在明确的适用范围内细化或收窄父级要求，不得默默豁免或覆盖。发现父子规则冲突时，澄清范围并修订权威正文，不按文档深度或索引顺序推断优先级。
- 规范应聚焦、简洁、可执行且容易找到。保留本仓库特定要求、重要流程和容易误判的边界；避免常识、重复内容、频繁变化的信息和长篇教程。临时规则写明失效条件。
- 若一个文件承载了多个可独立查找或维护的主题，应拆为聚焦的子规范，并由原文件保留简短说明和完整链接；不为拆分而制造不必要的层级。

## 通用目录树与索引规则

- 规范按树组织：根目录 `AGENTS.md` 是总索引，链接到 `agents/` 下的顶层规范或主题入口。主题有子规范时，主题入口保留为 `<主题>.md`，其子规范放在同名 `<主题>/` 目录中；更深层级沿用同一结构。没有子规范的主题直接使用单个 `.md` 文件。
- 每个入口先说明本层主题的整体范围和共用要求；若有子规范，在入口末尾设置子规范导航，逐项列出子规范名称、路径及适用场景。不要在父入口重复完整子规范，也不要要求根索引直接链接到每个深层文件。
- 每份规范都必须能从 `AGENTS.md` 沿索引链找到。新建子目录时同时建立或更新其父入口；没有父入口就先补入口，不留下未索引目录或孤立文件。
- 新增、移动、重命名、拆分、合并或删除规范，或改变规范职责、适用范围、入口说明或查找路由时，更新变更所在位置到 `AGENTS.md` 的所有受影响索引、链接和路径；涉及子树时检查其后代引用。只有正文变化且上述信息均不变时，才不必改索引。
- 根索引只维护顶层入口；每层入口负责自己的直接子项。更新到根索引是保持可达链路，不代表要把所有叶文件都直接列在根索引中。
- 删除或迁移子树时清理已无内容的目录；若目录仍有其他规范，不得连同未纳入计划的内容一起删除。

## 共用完成检查

- 若改动模块结构、路径或索引，从 `AGENTS.md` 沿受影响分支逐层走到目标文件；逐项确认可达、路径和链接有效、范围说明准确，且目标 agent 能按入口找到应读内容。
- 若改动规则正文，逐条对照已确认目标和仍有效的原要求，确认每项要求有唯一归属、适用范围和必要的前置条件、例外；拆分、合并、迁移或删除时，逐项核对原要求已迁移、保留或经用户确认废止。
- 若改动会改变操作步骤、判断或适用范围，按 [`workflow.md`](workflow.md) 的验证标准走读受影响场景；确认能从入口找到正确规则，并得到明确的下一步、暂停/用户决定点和完成条件。覆盖正常路径及本次改动涉及的边界和例外；无法判断的情况记为发现项，不自行补规则。
- 检查受影响规范及索引，确认没有重复、冲突、失效链接、孤立文件、孤立规则或失去归属的要求。
- 审查完整差异，保护已有改动，只保留已确认范围内的规范维护变更。

## 选择子规范

- 新建、修改、移动、重命名、拆分、合并或删除规范模块文件：阅读 [`module-maintenance/modules.md`](module-maintenance/modules.md)。
- 新增、修订、迁移、拆分、合并或删除模块内部规则：阅读 [`module-maintenance/rules.md`](module-maintenance/rules.md)。
- 本入口及其子规范自身也受以下流程约束。一次任务若同时改变规则正文和模块文件、目录、职责、路径或索引，两份子规范均适用；按各自前置要求安排步骤，并同时核验内容迁移和结构/索引结果。
